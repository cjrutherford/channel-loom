# Schedule precache delivery checkpoint

Status: incomplete; deployment gate not met. No image built or deployed in this work. The existing running image remains `awesometv:deployment-20261119-wqxetk` as observed with `docker compose ps`.

The existing cache implementation used a 24-hour lookahead and 100 GB configured budget by default, with one worker. It excluded the current airing and discarded jobs predicted to miss their deadline. This change includes current airings, admits late jobs in schedule order, queues original copies, checks source size and modification time before copying and file identity again afterward, checks the budget before each serial job, rejects a cache-directory source, and logs anticipated lateness. Eviction is deliberately disabled because playback does not hold a lease while FFmpeg reads. Once full, this implementation stops preparing more entries; its budget check is not a hard filesystem quota and does not account for all orphan files or external writers. Existing ready entries and old proxy jobs have not been migrated or validated by this change.

## Scheduled lease integration checkpoint

The private scheduled current/next resolver now selects a complete `copy` cache entry only when its catalog source path matches and its recorded copy length matches the source length, then obtains `Precache::acquire_ready(media_id, SourceIdentity)` before returning it. The cached location and `CacheLease` travel together into command preparation and the queued `PrivateItem`. Each item's destructor kills its process group and waits for the child before its lease drops, including cancellation; failed spawn releases the lease. Probe and subtitle extraction threads each own a cloned lease through their subprocess wait, including after the probe caller times out. The resolver falls back through `resolve_without_precache`, preserving source read-only behavior. Startup supplies the same `Arc<Precache>` to the engine and cache service. Global eviction remains disabled.

Focused verification: `cargo check -p awesometv-server` passed; `cargo test -p awesometv-server cache_ -- --nocapture` passed the two-child pressure/reap, timed-out real ffprobe FIFO, and real ffmpeg subtitle FIFO tests (plus one existing matching test); `cargo test -p awesometv-server scheduled_cache_resolution_pins_complete_copy_and_falls_back` and `cargo test -p awesometv-server failed_encoder_start_releases_cache_lease` passed. These use real subprocess lifetime and synthetic inputs, not actual cached media playback.

Remaining decision: extend guarded resolution and child ownership to catchup, DVR, and the legacy runner, or explicitly bypass precache for those consumers before any eviction is enabled. Explicit deletion remains unsafe for consumers still using the unguarded cloud resolver. Validate restart entries and source identity freshness, legacy entries and all removal paths before enabling eviction; the current identity comes from the stored entry and catalog path, without a fresh source stat during resolution. Next assignment: actual cached FFmpeg playback with a real media file, source unavailable, current and next encoders plus probes under pressure, then stop/reap and demonstrate release; include remaining consumers before considering eviction. ### Persistent eviction transition

Automatic admission now evicts the least recently released, unleased ready entry outside the upcoming-media keep set when required for the configured byte budget. A victim is removed from the leaseable index under its mutex and remains accounted as evicting; SQLite is conditionally changed from ready to failed/evicted before unlink. A database error leaves the file intact; an unlink error leaves the row non-ready and the victim unavailable and accounted until restart. Restart removes interrupted evictions in the configured cache directory and marks missing or incomplete ready files failed. Explicit removal also invalidates before unlink and rejects active leases and copies. `Precache::acquire_ready(id, &SourceIdentity) -> Result<Option<CacheLease>>` checks the local complete file and identity under the index mutex, without statting the source; lease clones pin it. The existing generic resolver bypass and private publisher lease ownership described above are the basis for enabling eviction; this does not establish fresh source identity.

Verification: `timeout 300s cargo test -p awesometv-server precache::lease_tests -- --nocapture` passed 8 tests, including SQLite/filesystem eviction, write-lock acquisition race, DB and unlink failures, and restart recovery. These are not real FFmpeg, browser, or deployment proof. Next: ready-cache correctness work must address asynchronous source identity refresh; then run real cached playback with source unavailable, active current/next/probe leases under eviction pressure, restart, and HLS decode/ordering checks. No NAS mutation, deployment, commit, or push in this slice.

## Simplified lease-draining refresh (2026-11-19)

The earlier generation-replacement requirement is superseded. The scheduled scan revalidates up to eight items per pass, rotates through the schedule, and marks changed ready entries refresh pending while existing leases finish. It then uses the existing SQLite eviction invalidation before unlinking and queues a reserved copy. An unavailable source leaves a matching ready entry usable with a deferred status; a changed catalog path cannot acquire the old entry through the scheduled resolver. Budget or fetch failure leaves a non-ready, explicit queue/failure state. No source stat was added to playback.
