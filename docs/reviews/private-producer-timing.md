# Private producer timing, 2026-11-18

Scope: local video private producer and paced public HLS. Existing worktree changes were retained. The ordered queue remains limited to two ten-second generations; only private input read throttling was removed. Publication still waits for each segment's scheduled end and preserves the existing cursor, duration, PDT, head and tail.

A focused FFmpeg comparison used the same 320x180/30 fps video plus AAC shape, two-second HLS segments, ultrafast x264 and a ten-second horizon. With `-readrate 1.0`, the first three closed segment files appeared at 2647, 4550 and 6456 ms after launch. Without input throttling they appeared at 81, 102 and 102 ms; the full ten seconds encoded in 142 ms. This isolates input pacing plus encoder/mux buffering as additive producer delay for this fixture, not an inherent six-second minimum. Results depend on encoding throughput; slow sources or hardware can still fall behind.

The focused production-command/publisher test `cargo test --offline -p awesometv-server production_command_produces_ahead_of_three_publication_deadlines -- --nocapture` passed: ready elapsed / publication lag in ms was (91, 998), (2056, 996), (4059, 994). Subsequent readiness is observed only after the preceding publication, so these are upper bounds on actual segment-close time. The schedule clock currently has whole-second resolution; its quantization contributes up to approximately one second to measured publication lag. Encoder launch, first atomic playlist appearance, observed closed-segment take, scheduled deadline, segment rename and playlist rename now carry monotonic timing logs. Polling observes closure; it does not claim the exact kernel rename instant.

The original calibrated real capture ran with unchanged 8000 ms ceiling, 2000 ms allowance and 15000 ms FIFO control. Before: `/tmp/awesome-wave6-wired-3/ts-timing.json` measured maximum age 7358 ms, tolerance 9358 ms, startup 7919 ms, and old/new source seconds 59/0. After: `/tmp/awesome-private-timing-after/ts-timing.json` measured maximum age 2501 ms, tolerance 4501 ms, startup 3062 ms, and old/new seconds 59/0. The transition arrived 3218 ms after its schedule and the delayed FIFO copy 18219 ms after it, correctly outside tolerance. HLS transition error was 18 ms. The server log in the after artifact records repeated publications across generations with bounded queue and no accumulating lag. Capture command: `STREAM_EVIDENCE_DIR=/tmp/awesome-private-timing-after timeout 180s python3 -u tests/e2e/stream_agreement.py`.

This fixture does not establish capacity for slower encoders, remote sources, unsupported-source handoff, audio continuity across multiple boundaries, or live deployment. Those are independent gaps outside this assignment.
