# Wave 2 renewal contract

Approved defaults: renewal appends at the exact maximum persisted end and never rewrites published rows, including manual edits. External and manual timelines are not renewal-owned. The caller supplies the clock and asks for at least seven days from that instant; triggering and retries belong to slice 5.

Generation state and appended rows must commit together under a SQLite write transaction, with the persisted boundary rechecked under that lock. State includes the definition identity and all mode-specific cursors, including override generators. A definition change rebases only future generation at the published end; it must not alter existing rows. Legacy timelines have no recoverable cursor and remain unowned and untouched by renewal. An explicit rebuild replaces the timeline and establishes a new generation epoch; it is not an append-only migration. A failure must leave both rows and state unchanged.

Use the existing fixed UTC offset; do not infer a named timezone or DST transitions. For competing overrides, highest priority wins, then lexicographically smallest stable override ID. Each generator must advance consistently across days and restarts, including when another override is selected. Classic, blocks and scripted definitions require their own reproducible continuation state; external imports and manual timelines remain untouched. Published edits are authoritative. A timeline with gaps or overlaps must not be silently repaired or truncated; fail explicitly when a safe append cannot be established.

Implementation status: `renew_channel_at(pool, channel_id, now)` supports generated classic and block channels, including classic or block scripted date overrides. Rebuilds with overrides establish resumable state. A generated rebuild records its continuation and definition fingerprint; renewal appends from the stored boundary through at least `now + 7 days`, committing rows and all generator state together using the compare-and-append transaction. Definitions are fingerprinted individually; a changed generator resets at the published boundary, without changing published rows. All current generators advance across each generated interval, including when another generator is selected. Expired overrides are ignored; selection uses inclusive UTC calendar dates, highest priority, then smallest ID.

The overlay splits classic media at UTC midnight and retains its remaining media offset for that generator. Block generation follows its existing range semantics at midnight and requires complete coverage. Every selected interval is checked for continuity before append. Existing generated classic/block state can be adopted when an override is added; legacy rebuilds with unavailable cursors still require a deliberate rebuild. External and manual/unowned timelines remain unsupported. The current fixed offset is UTC; no named timezone or daylight-saving transitions are inferred. No background renewal trigger is installed.

Focused evidence: `cargo test -p awesometv-server programming::tests` exercises both base modes with classic and block overrides, priority and stable-ID ties, future and expired dates across the March DST calendar transition, partial media, persisted prefix, restart, repeat, changed definition and concurrent renewal. The existing transaction tests cover rollback and conflicting appends. The append transaction also rejects a stale override-definition snapshot; a later retry can regenerate from the unchanged boundary. A database-wide input revision is captured before loading the channel and revalidated under the append write lock. Transactional triggers cover channel settings, base definitions, overrides, collections, collection membership, media and chapters, including change-and-revert edits. A concurrent unrelated input edit can conservatively fail renewal; the caller should retry. Legacy timelines cannot be resumed without an explicit rebuild.

Explicit rebuild is a replacement, not renewal: it can race another rebuild or external/manual replacement because its generated snapshot is not compared with the timeline at commit. Coordinate such operations until that separate replacement path gains concurrency protection. External replacement invalidates generated state, so a stale renewal cannot append after it.
