## Remote refresh

Startup launches the worker immediately, then six hours after success; failures back off from five minutes to six hours. Jellyfin and Emby are selected when their respective API keys are nonempty; defaults are Jellyfin `https://jelly.christopherrutherford.net` and Emby `http://localhost:8096`. Google cloud sources require enabled sources and at least one enabled root. Scheduled scans use a 20,000-item limit and a 30-minute outer deadline. Successful scans conservatively retain stale records to protect schedule references; removal reconciliation is not implemented. Jellyfin/Emby do not persist scheduled success status. Cloud last-success timestamps survive failures. See `wave-6-remote-refresh.md` for provider-specific retries, cancellation and evidence limits.

Cancellation before Jellyfin/Emby publication admission rejects the stage; an admitted transaction is allowed to complete and shutdown waits for it. Cloud cancellation similarly waits for admitted publication. Blocking provider work can outlive a timeout but cannot subsequently publish through the cancelled scan; it can retain threads and provider locks, so resource lifetime is not bounded. These guarantees do not imply rollback of a committed operation or bounded shutdown during a database transaction.

Local verification on 2026-11-18: `cargo test --offline -p awesometv-server` passed 98 tests, then `cargo build --offline -p awesometv-server` passed with 8 warnings; after adding the lock test, `cargo test --offline -p awesometv-server remote_refresh::tests` passed 3 tests. Tests use SQLite and local/mock providers; no real accounts or external clients were exercised. Configured worker startup and shared manual locks were inspected, while scheduling is tested with injected attempts. Credential sentinel coverage checks persisted errors, not captured tracing. Hosted CI provisioning and hosted CI execution remain unproven.
