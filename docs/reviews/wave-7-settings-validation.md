# Wave 7: settings validation

The only writable `/api/v1/settings` route is `PUT /api/v1/settings/language`. `/api/v1/config` is read-only and reflects environment configuration. Channel graphics/stream and cloud source routes configure separate resources; they are not global settings routes and were outside this slice.

The language request accepts optional string or null `audio_language` and `subtitle_language`, trimmed to at most 16 characters without control characters. `subtitle_mode` accepts `off` or `burn`, and defaults to `off` when omitted, preserving the existing request defaults. Errors identify the field and never include submitted values. All fields are validated before a single SQLite transaction writes the three keys. A retained subtitle language while subtitles are off is supported by the existing form and is not a conflict.

There are no numeric, URL, path, credential, or conflicting-field inputs in this API. URL/path constraints and cross-field rejection therefore cannot be demonstrated without inventing a contract or changing unrelated resource APIs. No filesystem existence checks were added. Existing stored values are not migrated. The existing read behavior maps an empty audio language to `eng`; this slice does not change that behavior.

Evidence: `cargo test -p awesometv-server settings_validation_preserves_sqlite_and_hides_input -- --nocapture` passed. The test sends real HTTP requests to the settings handlers backed by SQLite, exercises the 16-character boundary, overlength values, wrong types, invalid mode and control characters, checks field-specific errors and redaction, verifies every rejection leaves the prior settings intact, and reopens the database to check persistence. The test uses a focused router without production authentication middleware; hosted CI and system provisioning were not verified.

## Cloud persistence contract (2026-11-18)

The registered production provider is Google Drive. Folder `remote_id` is an opaque Drive ID (including `root` and shared-drive IDs), not a local filesystem path; empty IDs, control characters, slash and dot-segment IDs are rejected. Root paths are metadata, with display paths also used to form media names; they must be nonempty and contain neither controls nor `..` path segments. No local existence check is appropriate. New source config accepts an empty object or the existing omitted/null default: no Google-specific fields are currently consumed, and config is returned in source readback. Nonempty config is rejected to prevent credentials being stored in that unencrypted field. Existing rows are unchanged and can still contain previously stored config; operators should inspect and remove any secrets from them.

Credential JSON is checked before encryption and database writes. OAuth requires nonempty refresh token, client ID and client secret; service accounts require nonempty client email and private key. Optional `token_uri` must be a string accepted by the existing HTTPS endpoint policy: HTTPS, a host, no URL userinfo, and no explicitly internal host or private/loopback IP. Custom public HTTPS hosts remain supported. This is syntactic validation, not a DNS resolution or connectivity guarantee. Access tokens remain supported. Errors returned by the API do not echo submitted values. Root and credential validation precedes source creation, and invalid root updates precede database mutation. Existing stored rows are not migrated.

Evidence: `cargo test --offline -p awesometv-server cloud_validation_http_persistence -- --nocapture` passed 1 test on 2026-11-18. The focused HTTP router uses SQLite and tests OAuth and service-account URL rejection, credential and config redaction, source and root rejection without database changes, valid source creation, readback and database reopen. Production authentication middleware and actual Google connectivity are not exercised. The empty-config restriction applies to new sources; previously accepted nonempty config is not migrated or deleted. Cross-field rejection covers required fields within each credential type; no unrelated endpoint policy is claimed.
