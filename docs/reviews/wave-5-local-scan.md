# Wave 5: local scan reconciliation

Local scans are manual. The response retains `scanned`, `path`, and `media` and adds `complete`, per-path `files` (a null error means success), and `missing`. The default limit remains 50; use `limit: 0` for an unlimited scan. A limit that excludes files, a traversal error, or any ffprobe failure makes the result incomplete. Each local ffprobe has a 15-second deadline and bounded retained output. Invalid roots return an API error.

Inventory is scoped to the canonical scan root and kind. On a complete scan, previously observed paths absent from that inventory are marked missing in one transaction; rediscovered paths clear their marker. Incomplete scans can add or update successfully probed media but never mark unseen paths missing. Media rows and schedule/collection references are retained, including for missing paths. The marker is reported by the scan API; it does not filter library or playback queries. Existing media predating this change enters inventory when observed by a scan, so an already-absent legacy item cannot be inferred as missing. Overlapping roots have independent inventories. Scans of the same root should not be run concurrently: completion order determines its last marker state.

Evidence: `cargo test -p awesometv-server local_scan_reconciles_only_complete_inventory -- --nocapture` passed with a disposable SQLite database and generated WAV files. It checks additions, changed duration, removal marker with the original row retained, corrupt-file errors, a limit-truncated scan, dropping a completed report before persistence, and invalid root handling. The test models interruption before reconciliation; it does not kill a running server or exercise OS permission denial (the test environment may run with elevated privileges). Successful upserts before an interruption are allowed; missing reconciliation happens only after scanning and successful persistence.

Additional permission proof: `timeout 180s cargo test -p awesometv-server unreadable_directory_preserves_missing_markers -- --nocapture` passed (1 test, exit 0) as uid 1000 on Unix with ffprobe installed. The test inventories a WAV in a subdirectory, removes directory permissions, observes a traversal error and incomplete report, restores permissions, persists the incomplete report, and verifies no missing marker and the media row retained. It requires an environment that enforces the denial; elevated execution reports that the proof is unavailable and returns without asserting denial. Review confirms `WalkDir` errors and failed probes set incomplete, no symlink traversal occurs, and reconciliation marks missing only within its transaction after a complete report and successful upserts. A dropped request can leave successful upserts, while a detached blocking scan cannot itself reconcile. No live process-kill or cancellation race was tested; concurrent scans of the same root remain a documented limitation.
