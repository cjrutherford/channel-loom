The gap is not “another Tunarr.” ErsatzTV is deep but frozen and operationally heavy. ErsatzTV Next is a reliable engine with no scheduler, library, or UI. Tunarr is modern and active but deliberately simpler, with static lineups and a narrower content model. Nobody currently combines ErsatzTV's programming intent with a modern, trustworthy product.

02 · Context

The project changed under everyone

Feb 2026
Final release announced
ErsatzTV 26.3 is called the final release; repositories are archived. Scope creep and support burden are cited.
Mar 2026
ErsatzTV Next begins
A Rust rewrite of the streaming engine. Engine only: playouts in, HLS/M3U/XMLTV out. Scheduling explicitly out of scope.
Jul 2026
Legacy unarchived
Legacy is unarchived, renamed, and updated to use Next as its default engine. Feature development stays frozen; security updates continue.
Nov 2026
Tunarr adopts Next
Tunarr 2026.11.2 ships an experimental ErsatzTV Next backend. The ecosystem is converging on a shared engine, not a shared product.

04 · Opportunity

What “modern” should mean

Product thesis

Understandable

One channel studio. Start with channels, dayparts, shows, and breaks. Advanced rules appear only when needed. No five-schedule-type vocabulary before the first channel.

Reliable

A bad file, a missing item, a media-server outage, or an engine crash does not take the channel offline. Fallback, retry, and self-healing are defaults.

Fast

Warm segments, prefetch, and cached artifacts. Tune in in seconds, not ten. Copy/direct when the source already matches.

Observable

Per-channel now/next, viewer sessions, transcode speed, buffer depth, cache hits, errors, and a one-click diagnostic bundle.

Recoverable

Backup/restore built in. Safe migrations. Preview a schedule change and undo it. Never make the user erase history to fix a build.

Interoperable

HLS/TS, M3U/XMLTV, HDHomeRun, Plex/Jellyfin/Emby, OpenAPI, import/export, and an optional external playout/engine contract.

05 · Architecture

Small core, clear boundaries

Confirmed: Rust + React + SQLite + FFmpeg

Ingest

  • Local, Plex, Jellyfin, Emby
  • ffprobe, NFO, artwork
  • Subtitles, chapters, HDR
  • Incremental + deep scan
→

Program

  • Catalog + search
  • Collections, playlists
  • Dayparts + slots
  • Pure, deterministic timeline
→

Broadcast

  • Per-channel runtime
  • Segment cache + FFmpeg
  • HLS / MPEG-TS / HDHR
  • EPG from the same timeline

Scheduler is a library

No database, no wall clock, no random source. Inputs: plan, state, seed, time zone, interval. Outputs: items, state delta, warnings, coverage. This makes it testable and deterministic.

Engine is a worker

One runtime per active channel. Per-item FFmpeg for fault isolation. Atomic segment publish. Fallback producer. TS gateway for Plex. Idle stop. Tuner limits.

08 · Risks

What could sink it

Scope creep

The stated reason ErsatzTV wound down. Deep parity is broad. Mitigation: phased parity gates, a usable beta first, small core, say no.

Rust iteration speed

Compile times and a smaller contributor pool can slow the product. Mitigation: small crate graph, nextest, incremental CI, strong contributor guide.

Hardware / FFmpeg matrix

Every GPU and driver is a special case. Mitigation: probe, software fallback, conservative defaults, diagnostics, hardware CI.

Client compatibility

Plex needs TS; Jellyfin/Emby vary; HLS clients vary. Mitigation: TS gateway, test matrix, documented known issues.

Scheduler edge cases

Fixed starts, overruns, DST, impossible items. Mitigation: pure builder, invariants, simulation, golden tests, guardrails.

Transcode cost

Continuous channels are expensive. Mitigation: on-demand, copy mode, cache, limits, capacity calculator.

Security

Remote streams and scripts are dangerous. Mitigation: off by default, allowlists, SSRF/path/command protections, redaction.

09 · Decisions

Locked direction

Confirmed
✓
All-in-one product
Sources, library, scheduler, own engine, outputs, UI, and operations in one system.
✓
Deep parity in public v1
Classic, block/deco, sequential, scripted, external JSON, graphics, all media kinds. Phased so a usable beta lands first.
✓
Rust backend + React UI
Single binary, embedded web assets, SQLite default, FFmpeg sidecar. Small crate graph to keep compile times tolerable.
✓
Own streaming engine only
No dependency on ErsatzTV Next. Optional import/export of a public playout format for interoperability, implemented independently.
✓
Sources and clients
Local, Jellyfin, Plex, remote HTTP/RTSP/script. Plex, Jellyfin, Emby, Channels DVR, Kodi/TiviMate/generic IPTV.
✓
Multi-arch and auth
x86 GPU and low-power/ARM; single admin in beta, OIDC + roles in v1; MIT or Apache-2.0.
